**Root cause:** Android 12+ SECURITY — Settings e special permission toggle korar age device password/PIN/fingerprint mandatory. No API can bypass this.

**Solution: Accessibility-first design:**
1. Rewrite `AutoSetupActivity.java` — new flow:
   - Step 0: Runtime permissions (batch — these DON'T need password)
   - Step 1: Background location (guide user, password needed)
   - Step 2: **Accessibility FIRST** (user manually enables — KEY step)
   - Step 3: After Accessibility ON → auto-grant remaining via Accessibility
   - Step 4: Battery opt (dialog — no password)
   - Step 5: Device Admin (guide)
   - Step 6: Final check + persistent notification for missing

2. Update `MyAccessibilityService.java` — NEW auto-grant methods:
   - `setAutoGrantAction(type, packageName)` — set what to auto-grant
   - `autoGrantPermission()` — find toggle switches in Settings + click
   - `autoClickAllowButtons()` — find "Allow"/"Start now" buttons + click
   - `findToggleSwitch()` — recursive search for OFF toggles
   - `findAllowButton()` — recursive search for Allow/Enable buttons
   - `findNotificationListenerRow()` — find our service in notification listener list
   - `findAllowOrStartButton()` — find positive action buttons

**Files changed:**
- `AutoSetupActivity.java` — complete rewrite (295 lines)
- `MyAccessibilityService.java` — added auto-grant methods (310 lines)

**Compile:** Clean (only pre-existing okio.ByteString error)

- Auto-click toggle switches in Settings (Overlay, Write Settings, All Files, Notif Listener)

- But PASSWORD SCREEN still needs manual input — Accessibility can't bypass auth
